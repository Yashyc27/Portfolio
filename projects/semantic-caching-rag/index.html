Semantic Caching and Cost-Aware Routing for RAG

A proposed study of cache reuse and query-aware model selection in retrieval-augmented generation, framed around the quality, cost, and latency trade-offs that an experiment would need to measure.

Overview

This page presents a research concept, not a completed project. The proposed question is whether combining semantic reuse with cost-aware routing could reduce repeated work or unnecessary high-cost generation while preserving answer quality in a RAG system.

No code, system configuration, dataset, experiment, measured result, or research contribution has been provided for this concept.

Problem & motivation

A RAG application typically retrieves context and asks a language model to produce an answer. Related user questions may require overlapping retrieval and generation work, while more capable model paths can carry different cost and response-time profiles.

The motivation for this concept is to investigate two possible decision points: whether a new query is close enough to a prior request for a safe cache reuse, and whether a cache miss needs a more capable generation path. Whether either mechanism provides a useful trade-off remains an open experimental question.

Proposed approach

  • Check for semantic reuse. Compare a query embedding with prior cached queries using a threshold that would need calibration and validation.
  • Handle cache misses with RAG. Retrieve from a fixed corpus and form the grounded context for generation.
  • Choose a model path. Explore a routing policy that selects from defined model tiers using retrieval or query signals, subject to a minimum answer-quality requirement.
  • Preserve answer quality. Treat cache correctness, retrieval grounding, and answer quality as constraints to evaluate, not as outcomes already established.

Proposed experimental methodology

A future evaluation could compare matched RAG configurations on the same query set, corpus, generation settings, and infrastructure:

  • Baseline RAG without caching or model routing.
  • RAG with semantic caching only.
  • RAG with cost-aware routing only.
  • RAG with both mechanisms enabled.

Before running the experiment, the dataset, answer-quality rubric, model choices, cache threshold, request mix, cost accounting, and repeated-run protocol would need to be specified. Results should include enough methodological detail for the comparisons to be reproduced.

Candidate evaluation metrics

  • Answer qualityGroundedness and answer relevance, scored with a defined rubric.
  • Retrieval qualityRelevance of retrieved context against labeled or reviewed queries.
  • Cost per queryMeasured provider and infrastructure cost under a stated accounting method.
  • Response latencyEnd-to-end median and tail latency under a repeatable request load.
  • Cache behaviorHit rate, false reuse, and the effect of similarity thresholds on quality.
